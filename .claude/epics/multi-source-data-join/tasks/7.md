# Task: React/TypeScript前端架构迁移

## Description

将现有vanilla JavaScript前端升级到React 18 + TypeScript 5架构，为多源数据连接功能提供现代化的状态管理和组件化基础。保持现有透视功能不变的同时，建立可扩展的前端架构框架。

这是一个独立的基础设施任务，可以与后端开发并行进行。重点是建立新的技术栈，同时确保现有功能的平稳迁移。

## Acceptance Criteria

- [ ] React 18 + TypeScript 5环境完全配置
- [ ] 现有透视功能100%保持不变（拖拽、图表、导出等）
- [ ] 新的组件库和状态管理架构建立
- [ ] 构建系统升级（Webpack/Vite + TypeScript支持）
- [ ] 开发工具链完整（热重载、类型检查、调试支持）
- [ ] 所有现有页面和路由正常工作
- [ ] 性能指标不低于原版本（首屏时间、交互响应）
- [ ] 浏览器兼容性保持一致

## Technical Details

### 核心技术栈升级
- **React 18**: 利用并发特性处理大数据集渲染
- **TypeScript 5**: 严格类型检查，提升代码质量
- **Redux Toolkit**: 现代化状态管理，替代原生JS状态
- **React Query**: API调用缓存和同步机制
- **Material-UI v5**: 统一UI组件库，提升一致性

### 构建工具链升级
- **Vite**: 替换Webpack，提供更快的开发体验
- **TypeScript编译器**: 严格模式配置，全面类型检查
- **ESLint + Prettier**: 代码规范和自动格式化
- **Jest + Testing Library**: 现代化测试框架

### 文件结构重组
```
frontend/
├── src/
│   ├── components/        # 可复用UI组件
│   ├── pages/            # 页面组件
│   ├── store/            # Redux状态管理
│   ├── hooks/            # 自定义React hooks
│   ├── services/         # API调用服务
│   ├── types/            # TypeScript类型定义
│   ├── utils/            # 工具函数
│   └── legacy/           # 原有功能迁移缓冲区
├── public/               # 静态资源
├── tests/                # 测试文件
└── docs/                 # 组件文档
```

### 迁移策略
1. **渐进式迁移**: 先建立React框架，再逐步迁移功能模块
2. **功能保护**: 原有透视功能封装为React组件，保持API不变
3. **类型安全**: 为所有数据结构和API建立TypeScript接口
4. **测试驱动**: 每个迁移模块都有对应的单元测试
